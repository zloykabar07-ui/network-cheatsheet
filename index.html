1. Основные определения сети

Сеть — группа устройств, соединённых каналами связи и обменивающихся данными по общим правилам (протоколам).
Протокол — набор правил обмена данными (TCP, IP, HTTP, DNS и т.д.).
Пакет — единица данных, передаваемая по сети.
LAN (Local Area Network) — локальная сеть: дом, офис.
WAN (Wide Area Network) — глобальная сеть, интернет.
MAC-адрес — физический уникальный адрес сетевой карты (48 бит), вид 00:1A:2B:3C:4D:5E.
IP-адрес — логический адрес устройства в сети (см. раздел 2).
Порт — число 0–65535, определяющее службу: 80 — HTTP, 443 — HTTPS, 53 — DNS, 22 — SSH.
DNS — система доменных имён: переводит google.com → IP.
DHCP — протокол автоматической выдачи IP, маски, шлюза и DNS.
NAT — преобразование адресов: много устройств выходят в интернет через один публичный IP.
Роутер (маршрутизатор) — пересылает пакеты между сетями.
Коммутатор (switch) — соединяет устройства внутри одной сети.
Провайдер (ISP) — организация, дающая доступ в интернет.

2. IP-адрес, маска подсети, шлюз

IP-адрес

IPv4 — 32 бита, 4 числа 0–255 через точку: 192.168.1.10.
IPv6 — 128 бит, через двоеточия: 2001:db8::1.
Состоит из адреса сети + адреса хоста, границу задаёт маска.
Бывает частный (внутренний) и публичный (в интернете).

Частные диапазоны IPv4

ДиапазонМаскаКол-во адресов

Маска подсети

Показывает, какая часть IP — сеть, а какая — хост. Непрерывные единицы в старших битах.
МаскаПрефиксХостов в подсети
255.255.255.0/24254
255.255.255.128/25126
255.255.254.0/23510
255.255.0.0/1665 534
Формула: 2^(32 − маска) − 2 (минус адрес сети и broadcast).

Пример разбора

IP:        192.168.1.10
Маска:     255.255.255.0  (/24)
Сеть:      192.168.1.0
Хост:      .10
Broadcast: 192.168.1.255
Диапазон:  192.168.1.1 – 192.168.1.254
Шлюз:      192.168.1.1  (обычно)

Шлюз по умолчанию (Default Gateway)

Адрес устройства (обычно роутера), через которое уходят пакеты за пределы локальной сети. Обычно первый адрес подсети: 192.168.1.1 или 192.168.0.1.
Если шлюз неверен — интернет не работает, хотя локальная сеть может работать.

DNS-серверы

Обычно 8.8.8.8 (Google), 1.1.1.1 (Cloudflare) или адрес провайдера.

3. HTTP vs HTTPS

HTTP — протокол передачи гипертекста, данные идут открытым текстом.
HTTPS — тот же HTTP, но поверх шифрованного канала TLS/SSL.
ПараметрHTTPHTTPS
Шифрование❌ нет✅ TLS/SSL
Порт по умолчанию80443
Защита от перехвата❌✅
Подтверждение подлинности❌✅ сертификат
В браузере«Не защищено»🔒 замок
Где применяетсяинфо-сайты (устар.)логины, оплата, всё
Вывод: для любых форм, логинов и оплат — только HTTPS. HTTPS = HTTP + шифрование; современные браузеры помечают HTTP-сайты как небезопасные.

6. Типовые проблемы и что проверять

Алгоритм «нет интернета»

1. ipconfig — есть ли IP, маска, шлюз.
2. ping 192.168.1.1 (адрес шлюза) — доступен ли роутер.
3. ping 8.8.8.8 — есть ли выход в интернет.
4. ping google.com — работает ли DNS.

Быстрые решения

DNS не работает: nslookup google.com 8.8.8.8 — если так отвечает, а без указания сервера нет, проблема в DNS. Решение: прописать 8.8.8.8 вручную.
Wi-Fi «есть», интернета нет: проверьте, что IP не 169.254.x.x.
Сайт открывается по IP, но не по имени: тот же DNS.
